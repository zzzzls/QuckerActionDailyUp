# QuckerActionDailyUp
记录 Quicker 动作库中首次观察到的新增或修订 https://getquicker.net/Share/Recent

每天北京时间 08:00 / 21:00 通过 GitHub Actions 抓取（cron 为 UTC 00:00 / 13:00，实际执行可能延迟）。代码使用 `Asia/Shanghai`，不依赖运行机器的默认时区。

## 归档含义

- 原页面按“新动作（创建时间 48 小时内）”与“最近更新（更新时间 48 小时内）”分组，**不是按日期分组**。列表只提供相对更新时间；工具提示中的绝对时间是创建时间，不能用来确定修订日期。
- 修复后的文件名日期与 `inputtime` 都表示北京时间的**首次观察日**，不声称是动作实际发布/更新日。CSV 的 11 列名称、顺序与 UTF-8 编码不变。
- 读取现有 CSV，以 `动作URL + 修订版本 + 更新内容` 判断是否已经观察过。同一 URL 的版本或更新内容变化仍会写入；只有简介等展示字段变化不算新的修订。更新内容只规范化 CRLF 和首尾空白，不折叠内部换行。
- 同日多次执行合并新增记录，保留此前观察到的各版本及 `inputtime`。重复执行无新增时不改 CSV/HTML，不写入随运行增长的日志文件。
- 每日首次有效抓取保留原命名的 HTML 快照；同日后续发现新变化时，另存 `data/html/YYYY-MM-DD/<sha256>.html.gz`，不覆盖首份快照。
- 页面结构有效但没有新变化时，生成仅含表头的当日 CSV。缺少预期分组、表格或修订字段，以及抓取失败时，任务失败，不覆盖已有归档。
- 旧归档仅作为去重基线读取，**不自动修正日期或批量重写**。旧文件中的日期仍沿用旧逻辑。首次在空目录运行时，48 小时窗口内的所有当前版本会作为基线写入当日。

此列表只暴露当前版本，无法恢复两次抓取间已被替代的中间版本；停机超过窗口也可能漏记录。历史上相同签名再次出现会被视为重复，若上游在不改变修订版本与更新内容的情况下重新发布，仅凭此列表无法区分。

## 运行与回归测试

```sh
pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/crawler.py
```

测试使用离线页面和临时目录，覆盖连续两日、跨日窗口重叠、版本/内容变化、同日追加、空结果、重复运行、UTC 跨日及异常不覆盖；不会抓取线上页面或修改历史数据。
